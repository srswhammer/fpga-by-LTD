# FPGA CNN加速器的图像输入

这里存放已经完成预处理、可直接交给CNN加速器的单格数据，不是原始相机照片。

板上实时流程现使用 `board_bram.py`：Python预处理后直接把784个像素写入BRAM，不需要先保存或读取本目录。本目录用于离线对照；待硬件实现的具体接口见 [板上BRAM接口.md](../板上BRAM接口.md)。现有相机Overlay不能直接完成CNN预测。

## 文件位置

- `PNG/1`～`PNG/9`、`PNG/blank`：28×28单通道灰度PNG，供查看或由软件解码后发送像素。
- `HEX/1`～`HEX/9`、`HEX/blank`：与PNG一一对应的像素HEX文件，供RTL仿真或初始化存储器。
- `软件参考结果.txt`：270个样本的真实标签、INT8软件预测、9位输出和十类整数分数，供加速端核对。

本批共270张，数字1～9和空白各27张，来自“数字识别数据集_含空白_20261006”。使用当前交接包的sudoku_cell_v2处理（auto极性、20%裁剪边界阈值），未对原始图片或权重做改动。

目录名是真实标签：blank表示空白、内部类别0，不是数字0。软件正确269/270；`4/group_1_digit_4`真实为4，但软件预测为9。验证硬件计算一致性时，这个样本应与软件同样输出9，不应把其真实标签4当成当前模型的预期输出。

## 像素输入约定

| 项目 | 约定 |
|---|---|
| 一次输入 | 一张单格，不是整张数独 |
| 尺寸 | 高28、宽28，单通道；模型张量为1×1×28×28 |
| 数据类型 | UINT8无符号整数，0～255 |
| 背景与笔画 | 黑色背景、白色或灰色数字；保留灰度，不是仅0/255的二值图 |
| 发送顺序 | 逐行，从左到右、从上到下；地址=行号×28+列号 |
| 像素数据量 | 每格784个像素，即784字节；不包含PNG或HEX文件的编码/文本开销 |
| 数值尺度 | 保持原始UINT8像素；导出整数计算对应输入指数-8，不在输入前再除256、除255或转成有符号INT8 |

地址0是左上角，27是第一行右端，28是第二行左端，783是右下角。不要转置，不要再次反色、缩放或居中。

PNG是压缩图像文件，不能把整个PNG文件字节直接送入CNN。需要软件先解码为上述784个像素；也可以直接读取对应HEX中的像素值。

## HEX读取

每个HEX文件恰好784行，每行两个十六进制字符，表示一个8位无符号像素。00表示黑，FF表示255；没有0x前缀、逗号、地址或文件头。

RTL仿真示例（假设仿真工作目录为本文件所在目录）：

```verilog
reg [7:0] image_mem [0:783];
initial begin
    $readmemh("HEX/1/group_1_digit_1.hex", image_mem);
end
```

随后按像素地址0～783送入加速器。板上BRAM方案已在上述接口文档中约定：像素区从字节偏移0x100开始，32位小端打包每字4像素，通过REQUEST/ACK序号握手。它是需要新硬件实现的约定，不是已有相机Overlay的功能；不使用DMA的TLAST/TKEEP。

输出是9位独热：空白000000000，1为000000001，2为000000010，依次到9为100000000。软件十类分数顺序为空白、1、2、3、4、5、6、7、8、9；最终取最大分数对应的类别。

## 导出后续图片

在交接包根目录、使用已配置的Python环境执行：

```powershell
python -B preprocess.py --input "C:\新的单格图片目录" --output "预处理图像\新批次" --polarity dark_on_light
```

也支持`--input`指定单张图片。输入目录应只包含待导出的单格，程序保留相对子目录并生成PNG与HEX。同名输出会更新；不自动删除历史样本。导出不运行CNN，也不自动生成新的软件参考结果。

原始黑字浅底照片可明确指定dark_on_light，避免暗光下auto误判极性；已经标准化的28×28白字黑底输入使用light_on_dark或auto保持原像素，不要也强制dark_on_light。本批为复现已测成绩使用auto。

正常predict.py预测不会自动写图片，保存输入时应单独执行上述导出步骤。当前CNN结构、权重、移位和9位输出规则均不变；这些数据不是整张数独识别或开发板整机验证结果。
