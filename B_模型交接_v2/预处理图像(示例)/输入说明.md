# 预处理图像示例

本目录仅供离线查看、RTL仿真和计算结果对照。板上实时流程直接用Python预处理后写BRAM，不需要先保存这些文件。

- `PNG/1`～`PNG/9`、`PNG/blank`：28×28单通道灰度图片，每类27张，共270张。
- `HEX/`：与PNG对应，每文件784行，每行两位十六进制，表示一个UINT8像素。
- `软件参考结果.txt`：每张图片的真实标签、软件INT8预测、9位输出及十类整数分数。

输入为白字黑底、保留灰度，按行从左到右、从上到下排列。无需再次缩放、反色或除255/256。
PNG必须解码后才是像素；HEX必须解析后才是像素，不能把压缩文件或文本字节直接交给CNN。

板上32位打包、BRAM地址及写入顺序统一见 [板上BRAM接口.md](../板上BRAM接口.md)。
像素现在从BRAM字节偏移0开始，不再使用此前的0x100或请求/应答序号布局。

仿真中可把HEX加载到8位像素数组：

```verilog
reg [7:0] image_mem [0:783];
initial $readmemh("HEX/1/group_1_digit_1.hex", image_mem);
```

示例假设仿真工作目录为本目录；若读入32位RAM，需要按接口说明每4像素打包，不能直接把逐像素HEX当32位字读取。

当前软件正确269/270。唯一错例 `4/group_1_digit_4.png` 被判为9：硬件计算对照应与软件同样输出9，不能用真实标签4代替软件预期。
输出空白为000000000，1为000000001，依次到9为100000000。
