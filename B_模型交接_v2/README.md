# v2.4 数独单格识别 · 精简提交包

这是已经训练好的**预测包**，识别“空白、数字 1～9”，不识别数字 0。
模型结构和全部权重不变，不需要重新训练；2026-10-03已优化单格照片裁剪。

本包日常预测默认使用 **INT8**。裁剪边界掩码阈值从5%改为20%，减少纸张纹理扩大裁剪范围；保留中值滤波、灰度输入、缩放居中与9位独热输出，没有将整图二值化。标准28×28白字黑底输入保持原像素。

自采150张INT8复测：**149/150，99.33%**（原流程134/150，89.33%）；数字134/135，空白15/15。修正15张错例，没有新增错误；仍有一张4被判成9。这是同一批已分析图片的复测成绩，不代表独立照片或开发板整机准确率；不同光照和淡笔画仍需验证。

## 快速运行

本节是电脑上的CPU软件参考；板上硬件预测请使用上一节的`board_bram.py`。Windows依赖清单不要直接用于PYNQ板端安装。

在本目录打开 PowerShell，先运行自检：

```powershell
.\run.ps1 --self-test
.\run.ps1 --image "C:\图片目录\单格.png"
.\run.ps1 --image "C:\图片目录\单格.png" --backend int8
```

默认预测和自检使用 INT8；FP32仅保留显式 `--backend fp32` 的兼容入口。输入必须是**已裁好的单个完整数字或空白格**，不要直接输入整张数独。
背景判断不正确时，加 `--polarity dark_on_light` 指定黑字白底，或 `--polarity light_on_dark` 指定白字黑底。
内部类别编号0表示空白。日常预测的标准输出只包含9位编码；过淡笔画可能被当作空白候选，警告单独写到标准错误流。

浮点和INT8预测结果均与原v2.4同步，输出9位独热编码（左侧bit8、右侧bit0）：

```text
空白 000000000
1    000000001
2    000000010
3    000000100
4    000001000
5    000010000
6    000100000
7    001000000
8    010000000
9    100000000
```

Python调用 `Predictor('fp32').predict_one_hot(images)` 或 `Predictor('int8').predict_one_hot(images)`，
返回 `(编码字符串列表, 十类原始分数)`；`images` 是预处理好的UINT8单张或批量28×28图片。
编码保留前导零；硬件9位总线的数值为空白0、数字n为 `1 << (n - 1)`。
内部十类分数、模型结构、权重及TXT参数不变；`scores()`仍可单独获取原始分数。
直接处理图片可调用 `Predictor('int8').predict_image(image, polarity='auto')`，返回一个9位字符串。
`image`支持单格图片路径、PIL图片或NumPy数组；复用同一个Predictor即可避免反复加载参数。
低层 `scores()` 和 `predict_one_hot()` 约定输入为非空UINT8 `[28,28]` 或 `[N,28,28]`，不再重复手动检查。

本机 `run.ps1` 自动复用原 DigitCNN 环境，不会重新配置环境；模型和预处理代码不依赖原工程。
也可以直接执行 `python -B predict.py --self-test`。整个文件夹可复制到其他电脑。
在新电脑上，需要先安装 Python 和依赖；本次验证使用 Python 3.12.14、CPU PyTorch：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.ps1 --self-test
```

依赖清单固定为本机已验证的版本；新机器需能访问对应软件源。未打包虚拟环境，也不需要 torchvision、MNIST 数据集或训练目录来预测。
如 PowerShell 禁止执行脚本，可直接用 `.\.venv\Scripts\python.exe -B predict.py --self-test`。

## 模型与准确率

结构：`1×28×28 → Conv3×3(4)+ReLU → Pool2×2 → Conv3×3(8)+ReLU → Pool2×2 → Flatten200 → Linear10`。
卷积步长 1、padding 0；池化步长 2、向下取整，11×11 池化后为 5×5。
总计 **2346 个参数**。浮点输入为 UINT8 像素除以 **256**，不是 255；展平顺序为 CHW。

从零训练 40 轮，固定交付 seed42，按验证集选第 39 轮，而非按测试集挑模型。
2026-09-28 对提交包重跑完整测试，并与原版输出对照：

| 测试范围 | FP32 | INT8 |
|---|---:|---:|
| 标准测试，共 10020 张 | 9882 / 10020，**98.6228%** | 9878 / 10020，**98.5828%** |
| 仅数字 1～9，共 9020 张 | 98.4701% | 98.4257% |
| 固定轻微扰动测试，共 10020 张 | 98.0339% | 98.0339% |

标准测试由 **9020 张 MNIST 数字 1～9 + 1000 张合成空白**组成。两版本标准及扰动测试的合成空白召回率均为 100%；这不代表摄像头空白也能达到 100%。
INT8 标准准确率比 FP32 低约 **0.04 个百分点**。十类自检通过只证明基本可运行，不能代替上述完整测试。

历史验收已通过：复核验证集选轮记录、原始参数逐文件一致、完整标准/扰动集两版分数分别与原实现逐值一致、整数独立实现对照、图片预处理一致性，以及从其他目录启动和图片预测。
已随原工程同步精简：取消预测中的重复手动检查和每层累加范围扫描；使用原有已验证的参数，底层权重加载仍严格匹配。
共享版与本包的照片预处理像素规则一致；本包preprocess.py另增加了独立PNG/HEX导出入口，正常预测不增加文件写入。
之前精简代码时，591组预处理用例的中间图、最终像素及元数据与精简前一致；完整标准/扰动集浮点和整数分数也一致。这是历史精简验证，不是本次裁剪优化的像素不变声明。
2026-10-03的裁剪优化只影响数独照片入口；旧数字入口的150张处理结果保持一致。INT8原标准输入10020张仍为9878张正确（98.5828%），整数权重、偏置、移位规则和TXT数组均未改动。这个标准输入测试不经过照片预处理。
