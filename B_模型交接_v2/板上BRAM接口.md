# PYNQ预处理与BRAM输入

本包只负责：**单格图片 → Python预处理 → 写入BRAM**。
不在这里实现FPGA启动、等待完成或结果读取，也不加载bit文件。

## 板上调用

依赖PYNQ、NumPy、Pillow，不需要Torch。使用已经加载的Overlay：

```python
from board_bram import open_bram, write_image, write_pixels

# cnn_bram为示例名称，改成工程中AXI BRAM Controller的实际IP名。
bram = open_bram(overlay, 'cnn_bram')

# 输入已裁好的单格：图片路径、PIL图片或NumPy数组；不是整张数独。
pixels = write_image(bram, cell_image, polarity='dark_on_light')
# 返回时，784个像素已写入BRAM；接下来由外部控制程序启动CNN。
```

原始黑字浅底照片用dark_on_light；白字黑底用light_on_dark。
若已经是标准28×28白字黑底UINT8数组，直接调用 `write_pixels(bram, pixels)`，不再预处理。
预处理沿用现有灰度化、裁剪、缩放和居中规则；不做棋盘定位、81格切分或专门的网格线去除。

## 交给FPGA的数据

| 项目 | 约定 |
|---|---|
| 每次输入 | 一个数字或空白格 |
| 大小、类型 | 28×28，单通道UINT8，0～255，共784字节 |
| 像素含义 | 黑底、白色或灰色笔画，保留灰度；空白候选为全零 |
| 排列 | 行主序：从左到右、从上到下，不转置 |
| BRAM位置 | 从字节偏移0开始，最后一个像素在783（0x30F） |
| 写入方式 | PYNQ MMIO，196次32位写入，字节偏移0、4、8……780 |
| 字节顺序 | 小端：每字第一个像素放bit[7:0]，其余依次放高位 |
| 数值处理 | 不除255/256，不转成有符号INT8，不附加文件头 |

例如连续4个像素为 `01 02 03 04`，写入的32位整数就是 `0x04030201`。
第r行c列的像素字节偏移为 `r*28+c`。PL若使用32位字地址，第i字地址是i，而不是4*i。

## 最小硬件约定

- PS经AXI BRAM Controller写双口BRAM的A口，CNN从B口读；控制器只占A口。两端32位，输入容量至少784字节，可配置为1 KiB。AXI地址窗口大小以实际HWH为准。
- BRAM物理基地址由硬件工程分配，Python从HWH读取。BRAM同步读延迟由硬件端处理。
- **先写完一格，再启动CNN；CNN完成前不能覆盖这784字节。** 81格按此顺序复用缓冲区，不要连续写81格而不等待识别。
- 启动/忙/完成信号由加速器控制接口提供，外部程序负责协调。本文件不虚构其寄存器地址；写完BRAM本身不会自动启动CNN。
- BRAM这里只放像素，没有MAGIC、版本号、请求序号或结果字段，也不上传权重。此前0x100像素起始偏移的复杂方案作废，改为从0开始。
- 后续CNN输出仍为9位独热：空白000000000，1为000000001，……，9为100000000。结果接口不属于本次写图代码。

不需要把图片先保存为PNG/HEX再写BRAM。这里只传784个原始像素字节，不传PNG压缩文件或HEX文本。
