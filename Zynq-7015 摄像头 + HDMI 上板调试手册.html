准备工作与资料确认

先把"图纸"备齐，再动手——国产板卡的坑一半来自版本对不上、原理图查错脚位。
Note

裸板上电与基础状态确认

先不接摄像头子板、不接显示器，只验证主板本身能正常启动。原则：一次只引入一个变量。
通过标准
Hardware Manager 能稳定识别器件 + LED demo 能下载运行 + PS 串口能打印 Hello World，三者都成立，才进入下一阶段。

2

通信通道验证

打通后续调试要依赖的通道：串口打日志、SD 卡独立启动、网口（如果要远程传图）。
3

摄像头单独验证（并口 DVP）

这块板的摄像头接口是并口：cam_data[7:0] + cam_pclk/href/vsync + cam_scl/sda(SCCB)，没有 MIPI D-PHY，不需要调 Lane。先不接 HDMI，只验证「传感器能被识别 + 图像数据能进 DDR」。
通过标准
能稳定读到 Sensor Chip ID，且 VDMA 写出的一帧数据在导出后能正确解出图像内容（哪怕颜色不对、只要轮廓对得上），才算这一阶段通过。
展开：摄像头阶段常见坑
  • cam_xclk 没输出或频率不对：传感器 PLL 起不来，SCCB 完全无响应，这是第一排查点。
  • cam_rst_n / PWDN 时序不满足：复位保持时间不够、或 PWDN 极性接反导致传感器一直处于掉电状态。
  • 误插 OLED 模块到摄像头排针（或反之）：两者共用同一物理接口，模组丝印容易混淆。
  • href/vsync 有翻转但图像扭曲：多半是传感器寄存器里的输出格式（YUV422/RGB565/RAW）配置和 FPGA 这边的解析格式没对上，先确认两边格式一致。
4

HDMI 显示单独验证（FPGA 原生直出）

这块板的 HDMI OUT 没有 ADV7511 之类的独立编码芯片——差分对 clk_hdmi_out_p/n + data_hdmi_out_p/n[2:0] 直接从 FPGA Bank 引出，TMDS 编码是厂商写在 fabric 里的逻辑（多用 OSERDESE2 + TMDS_33 差分标准实现）。先不接摄像头，用内部彩条验证这条链路本身是否健康。
Note
原生 TMDS 直出对线材更敏感：调试阶段用短而优质的 HDMI 线（<1.5m），不要接转接头/延长线/切换器，出现"时有时无""偶尔花屏"优先怀疑线材和接触，而不是逻辑设计。
通过标准
彩条图案在显示器上稳定显示、无花屏/无滚动/无黑屏，且分辨率与官方例程配置的时序一致。
5

摄像头 + HDMI 联调

阶段 3、4 都独立通过后，再打通完整链路——这是唯一允许两个变量同时存在的阶段。
通过标准
显示器上能实时看到摄像头画面，遮挡镜头画面随之变化，长时间运行（建议 ≥10 分钟）无花屏/卡死/丢帧累积。
