# FPGA 与软件联调接口说明

## 1. 模型数值合同

结构：`uint8[28,28] → Conv(1→4,3×3) → ReLU/右移/饱和 → MaxPool(2×2) → Flatten(676) → FC(10)`。

| 数据 | 存储类型 | 小数位 F |
|---|---|---:|
| 输入图片 | uint8 | 8 |
| 卷积权重 | int8 | 6 |
| 卷积偏置和累加 | int32 | 14 |
| ReLU 后、池化、展平 | uint8 | 6 |
| 全连接权重 | int8 | 6 |
| 全连接偏置和十类分数 | int32 | 12 |

真实值 = 整数 × 2^-F。预处理输出的像素字节直接传入，不再除以 255 或 256。

卷积采用互相关，stride=1、padding=0。卷积后计算 `min(255,(max(acc,0)+128)>>8)`；饱和前不能先截低八位。池化是每通道 2×2、stride=2 的无符号最大值。展平索引为 `channel*169 + row*13 + column`。十个分数按有符号 int32 比较，并列最大时选择较小数字。

## 2. A 的接手顺序

1. 在交接根目录执行 `python "04_验证/验证模型.py"`。
2. 执行 `python "03_FPGA交接/导出FPGA参数.py"`，在 `generated_fpga/` 获得 MEM、BIN 和布局说明。
3. 读取 `hardware_reference.npz` 的第 0 张输入写 testbench。
4. 按 `conv_acc_int32 → relu_uint8 → pool_uint8 → flatten_uint8 → scores_int32` 逐层比较。
5. 第 0 张完全一致后扩展到十张，再补全零、全 255、随机和误分类输入。
6. 板上保存资源、时序、单张延迟、连续吞吐和端到端延迟。

NPZ 有文件头，不能将整个文件直接灌进 FPGA。导出的 MEM 每行一个补码整数，也不是已经按 AXI 总线宽度打包的数据。

## 3. C 的接手方式

`preprocess_digit_image()` 返回 `normalized_uint8`，形状 `[28,28]`。OpenCV 摄像头帧通常是 BGR，先转换为 RGB；ROI 中应只有一个完整数字。空白或低对比度应显示“未找到清晰数字”，不能沿用上一帧预测。

A 完成硬件后，保留同一份预处理字节，将 CPU `model.forward()` 替换为真实 Overlay/DMA 调用，同时保留 CPU 结果用于定位差异。

## 4. A/C 共同确认的协议

当前单图输入为 784 个 uint8，即 784 字节；输出为十个 int32，即 40 字节。还需确认：

- AXI 数据宽度、每拍字节排列和填充方式；
- DMA 输入输出长度、TLAST、TKEEP；
- 寄存器地址、启动、完成、复位、错误和超时；
- PS/PL 缓存 flush/invalidate 的责任；
- 参数使用 ROM 初始化还是运行时加载；
- 是否支持读取中间层调试数据。

当前没有假定 IP 名称、寄存器地址、bit/hwh 文件或已验证 DMA 驱动。
