# Z15 Sudoku LCD 恢复工程

为Z15和ATK 4.3英寸800×480 RGB LCD重建的独立显示工程，复用正点原子官方LCD时序和UART收发源码，固定屏幕型号4384及25MHz像素时钟，不用于其他屏幕。屏幕显示9×9盘面，原题黑色，补入数字红色。

`actual_result.json` 是2026-10-10现场摄像头切格后经组长CNN、求解器得到并人工核对的结果。`rtl/board_init.vh` 将该81字节结果作为启动画面；不代表bit文件包含CNN或求解器。

PL_UART：115200、8N1；帧为55 AA + 81字节 + payload求和低8位。每格bit7～5=0，bit4=0原题/1补入，bit3～0为0～9。接收完成后在垂直空白区更新；ACK=06，格式错误、校验错误或100ms接收间隔超时返回NAK=15。该协议是显示演示接口，不是组长CNN或求解器的控制接口。

本工程是独立PL bit。加载后替换当前CNN/求解或摄像头配置；必须先保存答案。用于显示验证，尚未整合到组长的system_wrapper中。

## 构建与验证

器件 `xc7z015clg485-2`，系统时钟50MHz。引脚来自官方19_lcd_rgb_colorbar和17_uart_loopback，PL_UART为AA11/AB11。在本目录运行 `vivado -mode batch -source build.tcl`，生成 `build/lcd_display.bit` 和时序报告。

测试文件 `tb_bridge.v` 验证整帧更新、ACK、校验、保留位及超时；`tb_pixels.v` 检查网格、原题黑色、补入红色。

2026-10-10此前蓝色版本在Z15上实测：启动画面显示本次求解答案，原题黑色、补入蓝色，用户提供屏幕照片核对。电脑通过PL_UART（当时为COM3）发送同一份81字节结果，收到ACK=06。由于发送内容与启动画面相同，本次未验证不同盘面的可见切换；摄像头、CNN/求解器和LCD仍通过分别加载bit顺序验证，尚未自动整合。

厂商源码文件保留原始版权声明。构建输出已忽略；源码存放在正式工程中，避免再次依赖临时目录。

2026-10-11按演示要求将补入数字改为纯红色（RGB ff0000），原题保持黑色；红色版本需重新加载bit后验证屏幕。
