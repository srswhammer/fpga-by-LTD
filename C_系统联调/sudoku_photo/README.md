# 整张数独照片识别

指定一张照片，一次完成棋盘定位、透视校正、光照修正、81 格切分及陶博然 v2 INT8 模型识别。照片下载到电脑后即可运行，不需要开发板保持开机。

## 分工与当前完成范围

丁昀熙负责的采集与图像处理链路：板上 Notebook 读取 DDR 中的 RGB565 图像并转为 RGB888；本目录程序在电脑上完成棋盘四角定位、透视校正、灰度处理、中值滤波、背景光照修正、81 格切分与边线裁剪，以及识别结果的顺序整理和每格一字节编码。

单格笔画提取、对比度归一化、缩放居中及 28×28 白字黑底 UINT8 输出，复用陶博然模型包中的 `preprocess_sudoku_cell`；随后调用其 INT8 识别函数和权重。预处理函数与 CNN 识别模型是两个步骤。

工程结构图中的图像处理功能已分段实现并完成当前样本验证。实现中先在整盘上进行中值滤波和光照修正，再切格。当前仍需手动将拍摄图片下载到电脑；尚未在板上验证本程序，也未将拍照、处理、识别接成一次运行的板上流程。后续工作是准备 Jupyter 调用入口、核对板上依赖并进行同图结果对照，再接入实时拍照结果。

## 首次准备

在本目录打开终端，使用 Python 3.10 或更高版本：

```powershell
python -m pip install -r requirements.txt
```

默认读取仓库中的 `B_模型交接_v2`。程序不修改模型源代码或权重。为避免仅运行整数推理仍需安装 PyTorch，程序从该包 `predict.py` 中提取原有 `integer_scores` 函数，先运行随包自检，再处理照片。`--model` 只能指定可信模型目录；模型更新后必须重新验证。

## 每次使用

```powershell
python recognize.py "C:\Users\dingy\Desktop\sudoku_test_1008_01.png"
```

默认保存在 `results/照片文件名/`。已有结果不会覆盖，再次运行请指定新目录：

```powershell
python recognize.py "C:\Users\dingy\Desktop\sudoku_test_1008_01.png" --output results/check_again
```

## 结果怎么看

- `predicted_board.txt`：九行九列识别数字，0 表示空格。
- `01_detected_board.png`、`02_rectified_board.png`：定位边框和校正后的棋盘。
- `03_raw_cells_contact.png`、`04_model_inputs_contact.png`：81 格原图及模型输入检查图。
- `cells_raw/`、`cells_28x28/`：每一格单独保存，文件名标明行列。
- `model_inputs_uint8.npy` / `.bin`：81×28×28 白字黑底 UINT8 输入，二进制共 63504 字节。
- `result.json`：数字、独热编码、棋盘位置和预处理记录；`scores_int32.npy` 是原始模型分数，不是概率。
- `one_hot_81.txt`：模型的 9 位独热字符串，1 对应最低位，空白为全零。
- `original_81bytes.bin` / `.hex`：显示侧原题数据，一格一字节，共 81 字节。bit7–5 为 0；bit4 为 0（原题）；bit3–0 为数字 0–9 的 8421 编码。当前没有求解，因此没有 bit4=1 的补入数字。

所有格子均按从上到下、每行从左到右排列。81 字节文件没有串口帧头、校验或握手，也不会自动发往 LCD；正式通信仍需与接收模块对接。

## 使用范围与验证

这是电脑端软件识别程序，不含数独求解，也不表示 FPGA 已完成 CNN 推理。拍摄时保持数字朝上、四角完整、棋盘尽量接近正方形；支持本次测试中的适度倾斜，不负责任意旋转方向纠正。定位失败会报错；成功输出后仍应查看检查图与数字。

2026-10-08 使用同一张手写题的四张实拍照片验证（10 月 7 日一张、10 月 8 日正面、倾斜、远距离三张），每张均与原题 81 格一致。这些是开发验证样本，不能代表其他题目和字迹的总体准确率。识别程序没有内置该题或答案。
