# 文件地图：每个文件是干什么的

交接文件按工作目的分成四层。代码文件名保留部分英文，是为了保持 Python 导入和模型字段稳定；目录、说明和关键注释均使用中文。

```text
B_模型交接/
├── README.md                         先读：结果、命令、三人入口
├── 文件地图.md                       本文件：逐项解释所有文件
├── requirements.txt                 运行所需的 NumPy/Pillow
├── .gitignore                       不上传缓存、虚拟环境和现场导出文件
├── 01_运行演示/                      C 从这里开始
│   ├── 运行演示.py                   命令行预测入口
│   ├── 演示.ipynb                    Jupyter 中文演示
│   └── 示例数字1.png                 最小图片输入样例
├── 02_模型核心/                      当前模型真正运行所需内容
│   ├── config.json                   模型结构、位宽和缩放规则
│   ├── parameters.npz                唯一一份整数参数
│   ├── paths.py                      集中定义四层目录路径
│   ├── preprocess.py                 任意单数字图片 → 28×28 uint8
│   └── integer_inference.py          28×28 uint8 → 十类整数分数
├── 03_FPGA交接/                      A 从这里开始
│   ├── 接口说明.md                   数值合同、验证顺序和 A/C 协议事项
│   ├── hardware_reference.npz        固定十张输入和逐层标准答案
│   └── 导出FPGA参数.py               从唯一参数生成 MEM/BIN
└── 04_验证/
    └── 验证模型.py                   检查参数哈希、形状和逐层结果
```

## 逐文件解释

| 文件 | 谁使用 | 作用 | 是否需要修改 |
|---|---|---|---|
| `README.md` | 全员 | 提供最短命令、当前结果和角色入口 | 状态变化时更新 |
| `文件地图.md` | 全员 | 解释全部文件以及目录关系 | 增删文件时更新 |
| `requirements.txt` | A/C | 只列运行需要的 NumPy、Pillow | 板上版本确认后再评估 |
| `.gitignore` | 维护者 | 排除 `.venv`、缓存和 `generated_fpga` | 一般不改 |
| `01_运行演示/运行演示.py` | C/全员 | 加载已有参数；未指定图片时跑固定十张，指定图片时先预处理 | 接 Overlay 时可参考，保留 CPU 版 |
| `01_运行演示/演示.ipynb` | C | 在 Jupyter 分三格加载模型、检查固定十张、观察图片预处理 | 可在副本中扩展界面 |
| `01_运行演示/示例数字1.png` | C | 检查图片路径、预处理和单张预测；真实标签为 1 | 可换自己的单数字图片 |
| `02_模型核心/config.json` | A/B | 第一版模型结构、定点小数位、舍入与饱和规则；是硬件数值依据 | 改动即产生新模型版本 |
| `02_模型核心/parameters.npz` | A/B/程序 | 唯一模型参数，包含卷积/全连接的权重和偏置 | 不手工编辑 |
| `02_模型核心/paths.py` | 程序维护者 | 所有脚本通过它找到模型、示例和标准答案 | 目录变化时统一修改 |
| `02_模型核心/preprocess.py` | C | 灰度化、判断背景、裁剪、缩放和重心居中，输出白字黑底 `uint8[28,28]` | 实拍数据验证后再调 |
| `02_模型核心/integer_inference.py` | A/B/C | CPU 整数标准答案，依次执行卷积、ReLU/缩放、池化、展平、全连接、argmax | A 的硬件逐层对齐它 |
| `03_FPGA交接/接口说明.md` | A/C | 解释类型、F 小数位、展平顺序、输入输出及待确定 AXI/DMA 项 | 协议确认后更新 |
| `03_FPGA交接/hardware_reference.npz` | A | 合并保存固定输入、标签和六个逐层结果，避免八个零散 NPY | 不手工编辑 |
| `03_FPGA交接/导出FPGA参数.py` | A | 现场生成四个 `.mem`、一个无头 `.bin` 和布局 JSON；输出到不上传的 `generated_fpga/` | 按硬件装载方式调整副本 |
| `04_验证/验证模型.py` | 全员 | 验证两个 NPZ 没被改坏、参数形状正确、固定十张逐层结果一致 | 模型升级时更新哈希 |

## 两个 NPZ 里具体有什么

`parameters.npz`：

- `conv_weight_int8`：卷积权重 `[4,1,3,3]`
- `conv_bias_int32`：卷积偏置 `[4]`
- `fc_weight_int8`：全连接权重 `[10,676]`
- `fc_bias_int32`：全连接偏置 `[10]`

`hardware_reference.npz`：

- `fixed_inputs_uint8`、`labels_int64`：固定十张输入及标签
- `conv_acc_int32`、`relu_uint8`、`pool_uint8`、`flatten_uint8`：中间层标准答案
- `scores_int32`、`predictions_int64`：最终十类分数及预测

这两个文件都有必要：前者让模型运行，后者让 A 判断硬件从哪一层开始算错。其余重复格式均改为现场生成，不放进交接目录。
