# digitcnn_v1_int8 第一版说明

状态：纯整数软件模型与交付文件已验证，可进入团队评审；尚未在 FPGA 上综合、实现或运行。

## 第一版包含什么

`digitcnn_v1_int8` 保留 float32 基线的网络结构：

```text
1×28×28
→ Conv 1→4, 3×3
→ ReLU
→ MaxPool 2×2
→ Flatten 676
→ Linear 676→10
→ argmax
```

推理过程中不使用浮点卷积、浮点全连接、除法或 softmax。数值规则为：

```text
输入 uint8 F=8
→ 卷积权重 int8 F=6，偏置/累加 int32 F=14
→ ReLU、加 128、右移 8 位、饱和
→ 激活/池化 uint8 F=6
→ 全连接权重 int8 F=6，偏置/分数 int32 F=12
→ 十个 int32 分数直接 argmax
```

## 精度结果

验收门槛在运行实验前已经固定：验证集和官方测试集相对 float32 下降不超过 0.5 个百分点，合成拍照图下降不超过 1.0 个百分点，固定 0～9 样本必须全部正确。

| 数据 | 数量 | float32 | int8/int32 | 变化 | top-1 一致率 |
|---|---:|---:|---:|---:|---:|
| 固定验证集 | 5,000 | 95.02% | 94.86% | -0.16 个百分点 | 99.48% |
| 官方测试集 | 10,000 | 95.30% | 95.21% | -0.09 个百分点 | 99.65% |
| 合成拍照图 | 1,000 | 94.40% | 94.10% | -0.30 个百分点 | 99.40% |

全部验收项通过。官方测试集上 float32 与整数模型只有 35 张图片的预测不同，其中有些是量化后改对，有些是量化后改错；最终净减少 9 张正确样本。

官方测试集 int8 分类别准确率：

| 数字 | 正确/总数 | int8 准确率 | 相对 float32 变化 |
|---:|---:|---:|---:|
| 0 | 971/980 | 99.08% | 0.00 个百分点 |
| 1 | 1113/1135 | 98.06% | -0.09 个百分点 |
| 2 | 963/1032 | 93.31% | -0.39 个百分点 |
| 3 | 966/1010 | 95.64% | +0.30 个百分点 |
| 4 | 951/982 | 96.84% | 0.00 个百分点 |
| 5 | 824/892 | 92.38% | -0.11 个百分点 |

数字 9 仍是最弱类别。第一版总体量化损失很小，下一轮提高识别率时应优先从训练数据、模型结构和真实摄像头数据入手，而不是继续增加这一版的定点精度。

## 饱和和实际整数范围

三个评估集的 ReLU 激活饱和次数均为 0：

| 数据 | 检查的激活数量 | 右移后最大整数 | 饱和数量 |
|---|---:|---:|---:|
| 验证集 | 13,520,000 | 209 | 0 |
| 官方测试集 | 27,040,000 | 209 | 0 |
| 合成拍照图 | 2,704,000 | 199 | 0 |

uint8 上限为 255，所以当前 F=6 留有实际余量。官方测试集实测卷积累加器范围为 -73,641～53,604，全连接分数范围为 -120,146～59,684，远小于 int32 上限。

## 发布目录

发布包位于 `../release/`：

```text
config.json                 定点规则、状态和验收结果
manifest.json               所有发布文件的 SHA-256、dtype 和形状
verification.json           独立读回验证结果
parameters/                 三种参数交付格式
reference/                  固定 0～9 的整数逐层答案
evaluation/                 预测、混淆矩阵、分类准确率和图表
```

### 参数格式

1. `.npy/.npz`：Python 和 Notebook 使用，保留形状与 dtype。
2. `.mem`：每行一个二进制补码十六进制整数，可供 Verilog `$readmemh` 或 testbench 使用。
3. `model_parameters_v1.bin`：无文件头的 6,852 字节紧凑参数包，int32 使用小端序。

紧凑二进制布局：

| 起始偏移 | 长度 | 内容 | 形状 |
|---:|---:|---|---|
| 0 | 36 | conv_weight_int8 | `[4,1,3,3]` |
| 36 | 16 | conv_bias_int32 | `[4]` |
| 52 | 6,760 | fc_weight_int8 | `[10,676]` |
| 6,812 | 40 | fc_bias_int32 | `[10]` |
| | 6,852 | 总计 | |

`.npy` 带 NumPy 文件头，不能整文件送入 PL；`.bin` 才是无头紧凑字节流。

### 固定整数参考

`reference/` 保存：

- `fixed_inputs_uint8.npy`：`[10,28,28]`；
- `conv_acc_int32.npy`：`[10,4,26,26]`；
- `relu_uint8.npy`：`[10,4,26,26]`；
- `pool_uint8.npy`：`[10,4,13,13]`；
- `flatten_uint8.npy`：`[10,676]`；
- `scores_int32.npy`：`[10,10]`；
- `predictions_int64.npy`：`[10]`。

A 的硬件应先在 sample 0 上比较卷积累加器，再比较 ReLU/右移、池化、Flatten 和最终分数；不应一开始只比较分类编号。

## 软件调用

```python
import numpy as np
from integer_inference import IntegerDigitCNN

model = IntegerDigitCNN.from_directory("runs/digitcnn_v1_int8")
images = np.load("../release/reference/fixed_inputs_uint8.npy")
result = model.forward(images, return_layers=True)

print(result.predictions)
print(result.scores_int32)
```

`integer_inference.py` 的卷积、ReLU、池化和全连接路径不调用浮点推理运算。它的电脑运行时间仅用于确认程序可执行，不能当作 FPGA 性能结论。

## 当前工程边界

这一版已经是可以交给团队评审的整数软件模型和硬件标准答案，但仍缺少：A 的 RTL/HLS 实现、AXI/DMA 实测、Vivado 资源与时序报告、板上逐层比对，以及 C 的真实 OV5640 数据测试。因此不能称为完成了竞赛项目或 FPGA 加速器。
