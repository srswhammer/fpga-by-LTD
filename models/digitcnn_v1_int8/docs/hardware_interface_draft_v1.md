## 逻辑事务

一次推理的逻辑输入输出先固定为：

```text
输入：784 个 uint8，28×28 白字黑底，行优先
控制：start / busy / done，可选 error / reset
输出：数字 0～9 对应的十个有符号 int32 分数
可选：PL 额外返回一个 uint8 argmax 类别
```

返回十个分数比只返回类别更利于调试和演示。十个分数共 40 字节，传输开销很小。PS 可以自行求 argmax，PL 的 argmax 可作为硬件功能和双方一致性检查。

## 当前推荐传输形式

面向最终性能，候选方案是：

- AXI4-Lite：控制和状态；
- AXI4-Stream + DMA：输入图片和输出分数；
- 第一版模型的 6,852 字节参数固化在 PL ROM/BRAM 中。

候选 32 位输入流打包规则：

```text
每拍 TDATA[7:0]   = pixel[4k+0]
每拍 TDATA[15:8]  = pixel[4k+1]
每拍 TDATA[23:16] = pixel[4k+2]
每拍 TDATA[31:24] = pixel[4k+3]
共 196 拍，最后一拍 TLAST=1
```

候选输出流规则：每拍一个有符号 int32 分数，顺序为数字 0～9，共 10 拍，数字 9 对应的最后一拍 `TLAST=1`。

这是候选打包方式，不是已经授权 A 开工的最终约定。A 可能根据现有 DMA、HLS/RTL 架构和板卡 PS 接口调整总线宽度。

## 模块内部顺序

```text
uint8 输入
→ int8 卷积权重乘加，int32 累加
→ ReLU
→ 加 128 后右移 8 位并饱和到 uint8
→ 2×2 uint8 最大池化
→ 按 channel→row→column 展平
→ uint8×int8 全连接，int32 累加
→ 十个 int32 分数
→ 可选 argmax
```

建议 A 保留调试模式，使固定 sample 0 能读回卷积/ReLU/池化中的少量指定位置。完整读回所有特征图不是最终运行必需，但早期联调能大幅缩短排错时间。

## 第一次与 A 讨论时必须确认

1. 使用 Verilog RTL、HLS，还是二者结合。
2. AXI4-Stream/DMA 是否已经有可复用工程，数据宽度是 32、64 还是其他。
3. `TLAST`、`TKEEP`、缓冲区对齐和缓存刷新要求。
4. 输入/输出是流式还是 BRAM 内存映射；PYNQ Python 端怎样启动和等待。
5. 参数是固化 ROM/BRAM，还是运行时从 DDR 加载。
6. 有符号乘法、右移、加 128、uint8 饱和是否按草案逐条实现。
7. Flatten 顺序是否为 `channel×169 + row×13 + column`。
8. 目标时钟、MAC 并行度、允许的 DSP/BRAM/LUT 预算。
9. 摄像头和显示模块已经占用多少 PL 资源和 AXI 端口。
10. 是否能提供综合、实现、时序和资源报告作为比赛证据。
